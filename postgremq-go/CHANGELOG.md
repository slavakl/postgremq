### ⚠ BREAKING CHANGES

* The postgremq.dev/mq module is gone; the schema is released as mq/vN GitHub releases. The CLI is installed with `go install postgremq.dev/postgremq-go/cmd/postgremq@latest` and is versioned with the Go client; its `completion` command is gone and usage errors exit with status 2.
* The Go modules moved to postgremq.dev/mq, postgremq.dev/postgremq-go (package postgremq) and postgremq.dev/cmd/postgremq, so update import paths. DialFromPool now takes a context, and Rust's Connection::from_pool is async. The CLI --target flag and the Go Migrate options are gone because migrations always go to the bundled version. Clients refuse to connect to a schema without postgremq.info() or with an unsupported protocol major; run the migrations first.

## 0.1.0 (baseline)

The state of the Go client (`postgremq.dev/postgremq-go`) when independent versioning started. It was never
published as 0.1.0; the first release is the next version above.

- Connection over a pgx v5 pool; publish (also on a caller's transaction),
  channel-based and handler-based consumers.
- Connection-level batched lease renewal and exclusive-queue keep-alive.
- Shared LISTEN session with reconnect and polling fallback.
- Queue-loss teardown (`Consumer.NotifyClose`, `WithQueueFatalHandler`,
  `ErrQueueGone`), graceful shutdown with a configurable deadline, retry with
  exponential backoff for transient errors.
- Schema migrations (`Migrate`, `GetMigrationStatus`), up only, to the latest
  embedded version.
- The `postgremq` CLI (`postgremq-go/cmd/postgremq`, until then the separate
  module `cmd/postgremq`): `migrate` and `status`.
- Optional OpenTelemetry metrics.
